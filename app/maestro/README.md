# Сценарии Maestro

Проверка приложения на телефоне без ручных нажатий: [Maestro](https://maestro.mobile.dev) сам нажимает кнопки
и сверяет, что на экране появилось нужное.

Запуск (телефон по USB, на нём уже стоит Homeplay и открыт сервер GOODMAN). Maestro 2.11 лежит в
`D:\APP\tools\maestro`, ему нужна Java 17 (`JAVA_HOME` на `D:\APP\tools\jdk-17.0.20.1+1`, в формате Windows).
Телефон на зарядке гаснет: перед прогоном разбудить экран, иначе Maestro видит заставку.

```bash
adb shell input keyevent KEYCODE_WAKEUP && adb shell input keyevent KEYCODE_MENU
maestro --device <серийный номер из adb devices> test app/maestro   # все сценарии, около 2 минут
maestro test app/maestro/02_search.yaml                              # один сценарий
```

Flutter отдаёт вкладки и строки списков одним текстом с переводом строки («Artists\nTab 1 of 4»,
«Gripir\nDanheim\n3:44»), а Maestro сравнивает текст целиком, поэтому такие места в сценариях написаны с `.*` в конце.
Русские названия сценариев в консоли Windows выглядят как «????» — это кодировка консоли, на работу не влияет.

- `01_home` — приложение открывается на сервере, видны библиотеки и поиск.
- `02_search` — общий поиск с каждой буквой: песня, исполнитель, альбом, папка; «2026-10» целиком; имя файла.
- `03_music_search` — поиск в «Музыке» с вкладки исполнителей, числа на вкладках.
- `04_playlist` — плейлист из долгого нажатия, поиск по нему, удаление; на сервере ничего не остаётся.

Сценарии рассчитаны на тестовые файлы сервера GOODMAN (Danheim, Pink Floyd «The Division Bell», фильм Vessels,
фото за 2026-09 и 2026-10). Оформление приложения и настройки телефона они не меняют, `clearState` не
используется: вход на сервер сохраняется.
